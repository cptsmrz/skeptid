## Overview

Modern digital communication is overwhelmed by sophisticated social engineering, generative synthetic media, deepfakes, and opaque binary payloads. Traditional detectors fail because they operate as black boxes—outputting an opaque "99% Real" or "99% Fake" metric with no accountability or supporting evidence.

**SKEPTID** takes a fundamentally different approach:
1. **Calibrated Risk, Not Proof:** Rather than claiming infallible ground truth, SKEPTID outputs a calibrated risk score (0.0 to 1.0), qualitative risk tiers (`LOW`, `MEDIUM`, `HIGH`), and an explicit confidence metric.
2. **Tri-Provider Consensus:** Every modality queries three independent provider layers (External LLM routers, Open-Source neural checkpoints, and SKEPTID-trained statistical/forensic heads) to eliminate single points of failure.
3. **Verifiable Forensic Evidence:** Every verdict is accompanied by verifiable, human-inspectable artifacts: highlighted text token spans, localized image anomaly heatmaps, frequency spectrograms, frame timeline scrubbers, and 16-segment Shannon entropy profiles.
4. **Lane Independence:** Strict isolation ensures Message, Media, Voice, and File pipelines operate independently without cross-contaminating intake states.

---

## Core Philosophy

- **Zero Fabricated Certainty:** When inspection models disagree (`max(risk) - min(risk) > 0.40`), SKEPTID explicitly flags provider disagreement and attenuates confidence rather than feigning consensus.
- **Offline-First Resilience:** In default `mock` mode, the entire platform—API, test suite, and web client—operates fully offline with zero external network calls and no third-party API keys required.
- **Server-Side Key Isolation:** When running in `live` mode, vendor API keys (Gemini, Groq, OpenRouter, Cloudflare) reside exclusively on the server. Zero credentials or keys are exposed to the browser.
- **No Hardcoded Metrics:** All benchmark results, holdout metrics, and confusion matrices are dynamically generated by evaluation scripts and recorded directly in `models/registry.json`.

## Three-Provider Consensus Architecture

Every modality engine dispatches requests concurrently across three decoupled provider tiers:

| Tier | Provider | Description | Characteristics |
| :--- | :--- | :--- | :--- |
| **P1** | **External Router** | Multi-vendor server-side routing across Gemini 3.8 Flash, Groq, OpenRouter, and Cloudflare Workers AI. | High semantic generalization; prompt-injection defenses; automatic vendor failover. |
| **P2** | **Open Source** | Public pre-trained checkpoints running locally via Hugging Face `transformers`. | Zero egress API cost; deterministic neural embeddings; graceful fallback if uninstalled. |
| **P3** | **SKEPTID Own** | In-house statistical classifiers and deterministic signal processing algorithms. | Sub-millisecond execution; zero network overhead; transparent coefficient-based explainability. |

### Disagreement & Consensus Logic
- **Unanimity:** When providers converge within a risk delta $\le 0.40$, scores are synthesized according to calibrated modal weights.
- **Disagreement Flag:** When $\max(\text{risk}) - \min(\text{risk}) > 0.40$, `verdict.disagreement` is set to `true`, confidence is penalized proportionally, and individual provider scores are surfaced in the UI.
- **Fail-Safe Integrity:** If all configured providers fail or timeout, the orchestrator returns an explicit `HTTP 503 Service Unavailable` rather than generating a fictitious verdict.

## Multi-Modal Intake Lanes & Engines

### 1. Message Lane (Text & Email)
- **Plain Text Analysis:**
  - Evaluates inputs across five granular labels: `safe`, `phishing`, `spam`, `threat`, and `bullying`.
  - **P3 Engine:** Pure-Python TF-IDF vectorizer (word unigrams/bigrams and character 3–5 grams) coupled to an SGD-trained multinomial logistic regression head (`models/text_v1.joblib`).
  - **P2 Engine:** Composite pipeline coupling `unitary/toxic-bert` (comment toxicity/threats) and `telecomsxchange/OpenTextShield` (SMS/email fraud).
- **Email Forensics (`.eml`):**
  - **Header Authentication:** Parses RFC 5322 headers; extracts and validates `Authentication-Results` for SPF, DKIM, and DMARC alignment.
  - **URL Intelligence:** Extracts all hyperlink targets; detects punycode homoglyph attacks, raw IP addresses, excessive entropy, and suspicious top-level domains.
  - **Lexicon Triggers:** Regex-based forensic scanner for urgency coercion, credential harvesting, extortion cues, and abuse keywords.
  - **Attachment Isolation:** Safely strips image/video attachments and offers one-click dispatch to the Media Lane.

### 2. Media Lane (Image & Video)
- **Image Forensic Suite:**
  - **Error Level Analysis (ELA):** Detects resaving inconsistencies and localized digital splicing by analyzing compression differential grids.
  - **2D Fast Fourier Transform (FFT):** Radially averaged power spectrum analysis isolating abnormal high-frequency energy spikes characteristic of synthetic GAN and diffusion generators.
  - **Noise Residual & PRNU Analysis:** Measures sensor pattern noise variance, kurtosis, and cross-channel covariance to uncover spliced composition boundaries.
  - **EXIF & Quantization Parsing:** Inspects camera metadata anomalies, missing quantization tables, and software signature tags.
  - **2D DCT & Gabor Wavelet Filters:** Frequency domain block analysis and multi-orientation texture inspection.
  - **Forensic Heatmap Generation:** Generates pixel-level anomaly maps highlighting manipulated regions without relying on opaque attention masks.
- **Video Deepfake Analysis:**
  - **Temporal Frame Sampling:** Uniformly extracts representative frames and keyframes across video containers.
  - **Inter-Frame Motion Jitter:** Calculates optical flow and frame-to-frame motion vector variance to spot temporal deepfake stutter.
  - **Interactive Frame Scrubber:** Delivers a timeline of per-frame risk scores with synchronized forensic inspection.

### 3. Voice Lane (Audio Forensics)
- **16-Band Mel Spectrograms:** Analyzes acoustic energy distributions across calibrated frequency bands.
- **Acoustic Jitter & Shimmer:** Measures cycle-to-cycle frequency and amplitude perturbations to detect synthetic neural voice clones.
- **Spectral Flatness & Rolloff:** Calculates Wiener spectral flatness and spectral centroids to distinguish natural vocal cords from synthetic vocoders.
- **Zero-Crossing Rate (ZCR):** Temporal analysis evaluating speech transients and unnatural unvoiced intervals.
- **Anomaly Head:** Scored via an unsupervised Isolation Forest anomaly detector trained on vocal distribution vectors.

### 4. Files & Binary Lane (Hex & Entropy)
- **16-Segment Shannon Entropy Curve:** Slices payloads into 16 uniform segments to detect packed sections, encrypted shellcode, or hidden payloads.
- **Byte Distribution Histograms:** Computes byte-frequency profiles and null-byte ratios to identify file formats and obfuscation.
- **Magic-Byte Sniffing:** Verifies true binary signatures against declared file extensions.
- **Embedded String Extraction:** Inspects printable ASCII/UTF-8 strings for embedded URLs, IP addresses, and suspicious system commands.

## Verifiable Evidence Layer

Every verdict returned by SKEPTID includes an `evidence` array containing verifiable forensic objects:

| Evidence `kind` | Description | Typical Payload Structure |
| :--- | :--- | :--- |
| `span` | Exact character offsets highlighting deceptive or threatening text spans. | `{"start": 12, "end": 45, "token": "verify your account", "category": "phishing"}` |
| `heatmap` | Base64-encoded visual anomaly overlay indicating spliced or manipulated image regions. | `{"image_data": "data:image/png;base64,...", "method": "ela_fft_composite"}` |
| `spectrum` | Radially averaged frequency or 16-band Mel power spectrogram energy distribution. | `{"energies": [0.12, 0.45, ...], "hf_energy_ratio": 0.38, "wiener_flatness": 0.04}` |
| `hex_entropy` | 16-segment Shannon entropy profile mapping packing or encryption boundaries. | `{"entropy_profile": [4.2, 4.3, 7.9, ...], "overall_entropy": 7.12, "is_packed": true}` |
| `timeline` | Temporal frame-by-frame risk and motion displacement progression across a video. | `{"frames": [{"frame_idx": 0, "timestamp_s": 0.0, "risk": 0.15}, ...]}` |
| `metric` | Tabular measurements of forensic indicators (noise kurtosis, pitch jitter, SPF/DKIM flags). | `{"jitter": 0.012, "spf": "pass", "dkim": "fail", "dmarc": "none"}` |

## API Reference

The interactive Swagger UI documentation is available at `http://localhost:8000/docs` when the server is running.

### Core Endpoints

| Method | Endpoint | Description | Input Format |
| :--- | :--- | :--- | :--- |
| `GET` | `/healthz` | Operational liveness probe. | None |
| `POST` | `/api/message/analyze` | Analyzes raw text or `.eml`/`.txt` files for social engineering and phishing. | JSON payload or `multipart/form-data` |
| `POST` | `/api/media/analyze` | Analyzes images, video, or audio payloads with forensic signal extraction. | `multipart/form-data` (`file`) |
| `POST` | `/api/binary/analyze` | Inspects arbitrary binary payloads, executables, or opaque files. | `multipart/form-data` (`file`) |
| `POST` | `/api/feedback` | Submits human verification feedback to drive active learning. | JSON (`analysis_id`, `correct`, `notes`) |
| `GET` | `/api/metrics` | Returns active model versions, holdout evaluations, and registry status. | None |
| `GET` | `/api/providers/status` | Reports live operational status and latency for P1, P2, and P3 across all modalities. | None |

## Model Registry & Gated Promotion

SKEPTID strictly rejects unverified metrics. All baseline evaluations, confusion matrices, and accuracy numbers are stored in `models/registry.json` and generated via automated evaluation against frozen holdout datasets (`data/holdout/`).

### Promotion Quality Gates
Before any candidate model is promoted to `primary` in `config/skeptid.yaml`:
1. **Holdout Evaluation:** Must evaluate on a frozen, multi-source test set (`holdout_v2` for text).
2. **Performance Threshold:** Text models must achieve macro-F1 $\ge 0.85$; image classifiers must achieve AUC $\ge 0.90$ across out-of-distribution generators.
3. **Full Label Coverage:** The candidate model must natively predict all modal labels (e.g., binary AI-vs-human detectors cannot be promoted to primary for full 4-class image classification).
4. **Automated Gate Execution:** Promotion eligibility is enforced programmatically by `skeptid.training.registry.promote_model_if_eligible`.

For dataset provenance, source URLs, and licenses, see [DATA.md](DATA.md). For detailed model architectures and label projections, see [MODELS.md](MODELS.md).

## Quick Start

### Prerequisites
- Python 3.12+
- `libgl1` and `libglib2.0-0` (required on Linux for OpenCV headless operations)

### Local Installation

```bash
# 1. Clone repository
git clone https://github.com/cptsmrz/skeptid.git
cd skeptid

# 2. Create and activate a Python 3.12 virtual environment
python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Linux / macOS:
source .venv/bin/activate

# 3. Install dependencies in editable mode
pip install -e .[dev]
```

### Environment Configuration

Copy `.env.example` to `.env` to configure optional external LLM vendors:

```bash
cp .env.example .env
```

```ini
# SKEPTID Environment Configuration
# Default mode is 'mock' (runs 100% offline with zero API keys)
SKEPTID_MODE="mock"

# External Vendor Keys (Required only when SKEPTID_MODE="live")
GEMINI_API_KEY=""
GROQ_API_KEY=""
OPENROUTER_API_KEY=""
CF_API_TOKEN=""
CF_ACCOUNT_ID=""
```

### Running the Server

Start the FastAPI application with live hot-reloading:

```bash
# Using Makefile
make run

# Or directly with uvicorn
python -m uvicorn skeptid.main:app --host 0.0.0.0 --port 8000 --reload
```

Open `http://localhost:8000` in your browser to access the SKEPTID interface.

### Running with Docker

Run SKEPTID in a production-ready, lightweight Debian container:

```bash
# Build the container
docker build -t skeptid:latest .

# Run container in mock mode on port 8000
docker run -p 8000:8000 -e SKEPTID_MODE=mock skeptid:latest
```

## Limitations & Honest Framing

As detailed in [LIMITS.md](LIMITS.md):
- **Probabilistic Risk, Not Proof:** Outputs represent probabilistic risk assessments supported by observable forensic indicators. They do not constitute legal or cryptographic proof of authenticity.
- **Generator Evolution:** ML detection models may degrade when exposed to novel, unseen generative model families, heavy recompression, or adversarial perturbations.
- **Rule-Based Fusion:** Multi-component fusion weights (such as email text, link intelligence, and header alignment) are calibrated heuristics. High-severity indicators prioritize security over false-positive suppression.
- **Transfer Encoders:** Pretrained models are explicitly documented as utilizing transfer features and are never claimed as "trained from scratch."
